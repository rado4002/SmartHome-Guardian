# Evaluation Checklist

Use this checklist to verify that the repository is ready for software engineering project evaluation.

## Core Requirements Artifacts

- Functional requirements are numbered and testable.
- Non-functional requirements include measurable verification criteria.
- Requirements traceability connects requirements to models and validation scenarios.

## Core Modeling Artifacts

- Use case diagram and use case descriptions are present.
- Domain model uses consistent terminology.
- System sequence diagrams align with the fully dressed use cases.
- Operation contracts are defined for important system operations.
- Class diagram aligns with the domain model and GRASP responsibility assignment.
- Communication, activity, and state machine diagrams are present for important flows.

## Architecture Artifacts

- Architectural drivers are linked to requirements and constraints.
- Component and deployment diagrams show the system structure clearly.
- Security view explains authentication, authorization, auditability, and protected communication.
- Technology decisions include context, decision, alternatives, and consequences.

## Validation Artifacts

- System test scenarios cover critical functional and non-functional requirements.
- Risk analysis identifies major project and system risks.
- Final report summarizes trade-offs, limitations, and lessons learned.
